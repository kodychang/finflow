# 12 — 連鎖店內部快取共享（CICS）

> Chain-Internal Cache Sharing。同一法人旗下的播放裝置之間，於開店前互相補充音檔快取，減少該企業的對外通信量。
>
> **這是銷售功能，不是基礎建設。** 平台的頻寬成本本來就是 ¥0（[11-p2p-evaluation](11-p2p-evaluation.md#21-頻寬成本0)）。本功能的價值全部在於**對連鎖客戶的訴求**，以及他們總部網路的實際負擔。判斷任何設計取捨時，請以此為準。

---

## 1. 適用範圍

**只在裝置之間網路可直接到達時運作。不建置 NAT 穿透、不架設中繼伺服器。**

| 情境 | 可用 | 說明 |
|---|---|---|
| 同一店舖內多台裝置 | ✅ | 大型店舖的多區域音響、百貨櫃位多樓層 |
| 企業網路（WAN／VPN／SD-WAN）連結的連鎖 | ✅ | 集中管理 IT 的連鎖（超市、藥妝、大型餐飲） |
| 商業設施內的同一營運者多店舖 | ✅ | 同一網段 |
| **各分店各自使用一般商用寬頻** | ❌ | **不支援，且不打算支援** |

最後一項是刻意的取捨。跨網際網路的穿透需要 STUN/TURN，會重新引入 [11-p2p-evaluation](11-p2p-evaluation.md) 已否決的複雜度與成本。**寧可讓功能適用範圍縮小，也不引入中繼基礎建設。**

> 銷售時必須誠實說明此限制。對「各店獨立寬頻」的連鎖客戶，本功能無效益，不應作為賣點提出。

---

## 2. 效益試算

以 **20 分店、企業網路連結** 的連鎖為例：

| 項目 | 數值 |
|---|---|
| 1 台每日預取量（24 時間分・256k AAC） | 約 2.8 GB |
| 快取共享**無**：對外通信量 | 20 台 × 2.8 GB = **56 GB／日** |
| 快取共享**有**：對外通信量 | 約 2.8 GB／日（第 1 台のみ） |
| 削減率 | **約 95%** |
| 月間削減量 | 約 **1.6 TB** |

實際削減率取決於各店情境設定的重複度。情境完全相同時接近上表；業種混合的連鎖（餐飲＋物販）會下降。

> 上表為上限值。`exclude_played_within_hours` 的設定下，每日實際輪替的曲目約為快取的三分之一，因此穩定運轉後的削減量會低於此。**銷售資料使用實測值，不使用本試算。**

## 3. 安全設計

### 3.1 內容定址帶來的天然防護

音檔以 `audio_sha256` 為識別碼（[03-data-model](03-data-model.md#3-曲目與版本)）。接收端**必定驗證雜湊**後才寫入快取。

因此：

- 惡意或損壞的 peer **無法注入竄改過的音檔** —— 雜湊不符即丟棄並回退 CDN
- 不需要對 peer 建立內容層級的信任
- 不需要簽章機制

這是 [03](03-data-model.md) 選擇內容定址的直接回報。

### 3.2 只共享音檔，不共享其他任何東西

| 可共享 | **絕不共享** |
|---|---|
| `commercial_key` 的音檔物件（依 `audio_sha256`） | 証明書 |
| | 再生ログ |
| | 曲庫差分・撤銷清單 |
| | 裝置金鑰・API token |
| | 情境設定・店舖資訊 |

**撤銷資訊絕不經由 peer 傳遞。** 理由見 3.4。

### 3.3 認證

裝置之間以**組織限定的短期 token** 互相認證：

```
GET /player/cache-token
Authorization: Device dk_live_...

→ 200
{
  "token": "cct_...",         // 伺服器簽章
  "org_id": "018f2b8f-...",
  "device_id": "018f2b90-...",
  "expires_at": "2026-09-02T06:00:00Z"   // TTL 24 時間
}
```

規則：

- 提供端**必須**驗證請求方 token 的簽章、有效期限、以及 `org_id` 與自身一致
- `org_id` 不一致 → 拒絕（跨客戶連線在協定層即不可能）
- 撤銷的裝置無法更新 token → **最長 24 小時內自動失去 peer 存取能力**

### 3.4 撤銷的安全性（最重要）

快取共享**不得**削弱撤銷能力。設計上以三重保障處理：

1. **撤銷通知只走中央通道** —— FCM 推播 ＋ `GET /player/catalog/delta`。peer 不傳遞撤銷資訊，因此不存在「透過 peer 散布過期清單」的攻擊面
2. **撤銷時同時停止提供** —— 裝置收到撤銷後，除了從本地快取刪除，也立即停止對 peer 提供該物件
3. **快取盤點證明（attestation）** —— 每次同步時裝置回報其快取內容的雜湊，伺服器驗證其中不含已撤銷曲目

```
POST /player/cache-attestation
{
  "device_id": "018f2b90-...",
  "cached_count": 1284,
  "inventory_hash": "sha256:...",   // 快取中所有 audio_sha256 排序後的雜湊
  "taken_at": "2026-09-01T05:00:00Z"
}

→ 200 { "status": "ok" }
→ 200 { "status": "purge_required", "purge": ["a3f2b1...", "..."] }
```

伺服器保存最近一次盤點於 `venue_devices.cache_inventory_hash`。**盤點不符或逾期未回報的裝置，自動停用快取共享**，直到恢復正常。

> 這一項讓撤銷能力**不因快取共享而下降**：即使某台裝置遺漏了撤銷推播，下次盤點時會被強制清除。

## 4. 運作規則

| 項目 | 規格 |
|---|---|
| **預設狀態** | **關閉**。需組織管理者明示同意後啟用 |
| 探索方式 | mDNS/DNS-SD（`_kanade-cache._tcp.local`）＋ 手動 peer 清單（WAN 連結時） |
| 傳輸協定 | HTTPS over LAN，自簽憑證 ＋ token 認證 |
| **執行時機** | **僅限預取視窗**（預設：開店前 2 小時、及閒置時段） |
| **播放中** | **絕不使用 peer 傳輸。** 播放一律讀取本地快取 |
| 頻寬上限 | 預設 2 Mbps／台，可設定 |
| 讓步規則 | 裝置需為即將播放的曲目取得資料時，立即中止 peer 傳輸 |
| peer 逾時 | 首位元組 5 秒 → 逾時即回退 CDN |
| 失敗處理 | **快取共享純屬最佳化。停用時所有功能必須完全正常** |

**「播放中絕不使用 peer 傳輸」是不可妥協的規則。** 音樂中斷對店家是營業事故，不能讓它取決於另一台裝置的狀態。

## 5. 同意與契約

連鎖客戶的 IT 部門會審查此功能，因此同意流程必須具體。

啟用畫面須明確說明：

```
┌────────────────────────────────────────────┐
│  拠点間キャッシュ共有                        │
│                                            │
│  貴社の店舗に設置された端末どうしが、        │
│  開店前に音源データを相互に補完します。      │
│                                            │
│  ✓ 対象は貴社所有の端末のみ                 │
│    他社の端末とは一切通信しません           │
│  ✓ 共有されるのは音源ファイルのみ           │
│    店舗情報・再生ログ・証明書は含みません   │
│  ✓ 営業時間中は動作しません                 │
│    開店前および待機時間帯のみ               │
│  ✓ いつでも無効化できます                   │
│                                            │
│  想定される削減量: 約 1.6 TB／月            │
│                                            │
│  [ 同意して有効化 ]   [ 今は有効にしない ]   │
└────────────────────────────────────────────┘
```

- 同意者・同意日時を記録（`cache_sharing_consented_by` / `_at`）
- 契約に附屬書として本機能の説明を添付
- 無効化は次回同期で即時反映

## 6. 資料模型の追加

```sql
ALTER TABLE organizations
  ADD COLUMN cache_sharing_enabled       boolean NOT NULL DEFAULT false,
  ADD COLUMN cache_sharing_consented_at  timestamptz,
  ADD COLUMN cache_sharing_consented_by  uuid REFERENCES users(id);

ALTER TABLE venue_devices
  ADD COLUMN cache_share_enabled         boolean NOT NULL DEFAULT false,
  ADD COLUMN cache_inventory_hash        bytea,
  ADD COLUMN last_attestation_at         timestamptz;

-- 削減効果の可視化。営業資料の根拠となるため日次で保持する。
CREATE TABLE cache_transfer_stats (
  id                  bigserial PRIMARY KEY,
  org_id              uuid NOT NULL REFERENCES organizations(id),
  device_id           uuid NOT NULL REFERENCES venue_devices(id),
  stat_date           date NOT NULL,
  bytes_from_peers    bigint NOT NULL DEFAULT 0,
  bytes_from_cdn      bigint NOT NULL DEFAULT 0,
  bytes_served_peers  bigint NOT NULL DEFAULT 0,
  peer_fetch_failures integer NOT NULL DEFAULT 0,
  UNIQUE (device_id, stat_date)
);

CREATE INDEX ON cache_transfer_stats (org_id, stat_date DESC);
```

## 8. 実装フェーズ

[09-roadmap](09-roadmap.md) の Phase 3。前提条件：

- 商用播放器が安定稼働していること（Phase 2 完了）
- 撤銷流程の演習が完了し、6 時間以内の停播が実証されていること
- 連鎖客戶（20 店以上）が少なくとも 1 社契約済みであること

**最後の条件が重要。** 実際の顧客なしに本機能を作ると、企業網路の実態（VLAN 分離、プロキシ、帯域制御）に合わない設計になる。**最初の連鎖客戶と一緒に設計すること。**

### 受入基準

| 項目 | 基準 |
|---|---|
| 削減率 | 同一情境の 10 台構成で **80% 以上** |
| 播放への影響 | 音切れ・遅延 **0 件** |
| 撤銷の実効性 | 快取共享有効時も停播まで **6 時間以内** |
| 盤点の検出力 | 撤銷済み曲目を保持する端末を **100% 検出** |
| 無効化 | 無効化後、全機能が正常動作すること |

## 9. やらないこと

| 項目 | 理由 |
|---|---|
| 跨組織（他社との）共有 | [11](11-p2p-evaluation.md#3-b2b-特有的否決理由) の否決理由がそのまま該当 |
| NAT 穿透・TURN 中継 | 中継基礎建設を持たない方針 |
| 播放中のピア伝送 | 音切れリスク。営業事故になる |
| 撤銷情報のピア伝播 | 撤銷能力の中央集権性を維持する |
| 聽眾端への展開 | 別途評価（[11 情境 C](11-p2p-evaluation.md#42-情境-c聽眾端電台模式)） |
