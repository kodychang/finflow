# 06 — 商用播放器規格

商用播放器與一般聽眾端播放器**完全分離**，是獨立的產品線。它的核心要求不是功能豐富，而是：**絕不出錯、絕不停止、絕不被污染。**

---

## 1. 平台

| 形態 | 技術 | 優先度 |
|---|---|---|
| **Android App** | Kotlin + ExoPlayer（Media3） | P0 —— 主要形態 |
| Web（kiosk 模式） | PWA + hls.js | P1 —— 備援與試用 |
| 專用硬體 | 預裝 App 的 Android box | P2 —— 降低導入門檻 |

**為何以 Android 為主：** 需要穩定的背景播放、離線快取、開機自動啟動、裝置鎖定。這些在瀏覽器中無法可靠達成。

**專用硬體的價值**在於「插上就能用」—— 對餐飲業店主而言，「不必學習操作」的價值極高，且能徹底避免員工用店內裝置切換到其他音源。

---

## 2. 情境引擎（Scene Engine）

這是產品差異化的核心。店家**不選歌**，只設定情境規則。

### 2.1 情境維度

| 維度 | 取值 |
|---|---|
| 時段 | 開店前 / 朝 / 昼 / アイドル / 夕 / 夜 / 閉店前 |
| 曜日 | 平日 / 週末 / 祝日 |
| 天候 | 晴 / 曇 / 雨 / 雪（透過氣象 API 依店舖所在地取得） |
| 混雑度 | 静か / 普通 / 混雑（店家手動或 POS 整合） |
| 業種預設 | カフェ / レストラン / 居酒屋 / 美容室 / 物販 / クリニック |

### 2.2 情境規則

```json
{
  "scene_id": "018f2c05-...",
  "name": "平日 午後 雨",
  "conditions": {
    "weekday": ["mon","tue","wed","thu","fri"],
    "time_range": ["14:00", "17:00"],
    "weather": ["rain"]
  },
  "selection": {
    "bpm_range": [70, 95],
    "energy": "low",
    "has_vocals": false,
    "genre_tags": ["ambient", "lofi", "jazz"],
    "exclude_played_within_hours": 72
  },
  "priority": 10
}
```

多條規則命中時取 `priority` 最高者。無規則命中則落回業種預設。

### 2.3 選曲演算法

```
1. 依情境條件過濾商用曲庫
2. 排除 exclude_played_within_hours 內在本店播放過的曲目
3. 以 CLAP embedding 對情境中心向量做相似度排序
4. 取 top 200，加權隨機抽樣（避免每次順序相同）
5. 檢查銜接：相鄰曲目的 BPM 差 < 20、調性相容
6. 產生 4 小時份的播放佇列，預先快取
```

> **`exclude_played_within_hours` 是「不會聽膩」的技術實現。** 預設 72 小時，Custom 方案可設更長。同時要監控：若曲庫規模不足以支撐該設定，需自動放寬並在後台告警 —— 曲庫成長速度是這個賣點的前提條件。

## 3. 離線快取

**店內網路不穩不能導致音樂中斷。** 這是 B2B 客戶的底線要求。

| 項目 | 規格 |
|---|---|
| 快取容量 | 至少 4 小時份（約 500 MB）；預設 24 小時份 |
| 預取時機 | 開店前 2 小時、閒置時段 |
| 淘汰策略 | LRU，但保留當前佇列與次一情境的曲目 |
| 完全離線時 | 以本地快取循環播放，並記錄事件待補傳 |
| 最長離線容許 | **7 日** —— 逾期播放器進入靜音並顯示告警 |
| 快取加密 | 檔案以裝置金鑰加密儲存，防止直接複製外流 |
| 拠点間共有 | **預設關閉。** 同一法人內的裝置可於預取視窗互相補充快取 —— 規格見 [12-chain-cache-sharing](12-chain-cache-sharing.md)。播放中絕不使用 peer 傳輸 |

**7 日上限的理由：** 曲庫撤銷必須能生效。若裝置可無限期離線播放，被撤銷的曲目將永遠無法從店內移除，權利鏈即失去閉環。

## 4. 音量標準化

BGM 服務的生死線。**曲目間音量跳動比選曲不佳更容易導致解約。**

| 項目 | 規格 |
|---|---|
| 目標響度 | **-16 LUFS**（integrated） |
| True peak 上限 | **-1.0 dBTP** |
| 實作 | 轉檔時量測並記錄；播放時套用增益（不重新編碼） |
| 動態範圍 | LRA > 12 的曲目不納入商用曲庫（BGM 不適合大動態） |
| 交叉淡入淡出 | 2〜4 秒，依 BPM 調整 |
| 曲間靜音 | **0** —— 絕不出現無聲空隙 |

播放器套用的是 `track_versions.lufs_integrated` 計算出的靜態增益，非即時壓縮 —— 即時處理會改變音色，且在低階裝置上不可靠。

---

## 5. 裝置鎖定

**任何外部音源接入都會摧毀「管理外」保證。**

| 措施 | 說明 |
|---|---|
| Kiosk 模式 | Android screen pinning，禁止離開 App |
| 禁用藍牙音源接收 | App 啟動時關閉 A2DP sink |
| 禁用 AUX 輸入 passthrough | — |
| 單一輸出裝置 | 僅允許已設定的輸出端 |
| 遠端管理 | 店主可從手機控制音量、切換情境、暫停 |
| 裝置撤銷 | 後台可立即撤銷裝置金鑰（離職員工、裝置遺失） |
| 開機自啟 | `BOOT_COMPLETED` 後自動啟動並恢復播放 |

> 這條規則必須寫入店家條款：**於本服務裝置上播放其他音源，將使管理外証明書對該時段失效。** 否則員工拿手機接藍牙放 Spotify，記錄與現實脫節，証明書就成了不實文件 —— 那比沒有証明書更危險。

---

## 6. 同步

| 項目 | 頻率 |
|---|---|
| 曲庫差分同步 | 每 6 小時 |
| **緊急撤銷推播** | 即時（FCM），高危事件用 |
| 情境設定同步 | 變更時即時 + 每 6 小時 |
| 再生ログ 上傳 | 每 15 分鐘，或累積 100 筆 |
| 心跳 | 每 5 分鐘（`venue_devices.last_seen_at`） |

**緊急撤銷推播是權利鏈的最後一哩。** 從發現污染到店內停止播放的目標時間：**推播可達裝置 < 5 分鐘；離線裝置最長 6 小時（下次同步）。**

## 7. 店主端 UI

原則：**一個畫面能看完，三次點擊能完成任何操作。**

```
┌─────────────────────────────┐
│  ◯◯カフェ 渋谷店             │
│                             │
│      ♪ 再生中                │
│      「朝の光」 Yuki Aoi     │
│      ▁▃▅▇▅▃▁                │
│                             │
│  シーン: 平日 午後 雨 ▾      │
│  音量:   ━━━━━●━━━          │
│                             │
│  [ 一時停止 ]  [ スキップ ]  │
│                             │
│  ─────────────────────────  │
│  ✓ 管理外証明書 有効         │
│    KND-2026-000123          │
│    2027年8月31日まで         │
│  ─────────────────────────  │
│  [ 証明書を表示 ]            │
│  [ 再生ログを出力 ]          │
└─────────────────────────────┘
```

**「証明書を表示」必須在首頁一鍵可達。** 這是店主在被詢問的當下、緊張狀態下要用到的功能 —— 不能埋在設定選單第三層。

## 8. 失效模式與處理

| 情況 | 行為 |
|---|---|
| 網路中斷 | 以快取繼續播放，UI 顯示小型離線標示 |
| 快取耗盡且離線 | 循環播放已快取曲目，記錄告警 |
| 離線超過 7 日 | 停止播放，顯示「オフライン期間が上限を超えました」 |
| 訂閱欠費 | 寬限 14 日照常播放；逾期降級為 Free 情境並顯示提示 |
| 曲目被撤銷 | 若正在播放，於曲末切換（不中斷當前曲目）；並從佇列移除 |
| 裝置金鑰被撤銷 | 立即停止播放，要求重新綁定 |
| App 崩潰 | 前景服務自動重啟並恢復播放位置 |

「曲目被撤銷時不中斷當前曲目」是刻意的取捨：突然靜音會讓店內顧客察覺異常，而多播放至多數分鐘的風險遠低於此。若為極高危事件，後台可標記 `hard_stop` 強制立即中斷。
