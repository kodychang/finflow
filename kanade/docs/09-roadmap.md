# 09 — 路線圖

各階段皆有**明確的中止條件**。若驗收標準未達成，正確的動作是停下來重新檢視假設，而不是進入下一階段。

---

## Phase 0 — 假設驗證（2〜3 週，不寫程式）

整個產品建立在一個尚未驗證的假設上：**店家對現有 BGM 服務的主要不滿是「聽膩」。**

| 工作 | 產出 |
|---|---|
| 訪談 15〜20 家日本小型店舖（餐飲／美容／零售） | 訪談記錄 |
| 確認：現用服務、月付金額、前三大不滿 | 痛點排序表 |
| 確認：是否曾被詢問著作權、如何應對 | 証明書需求驗證 |
| 諮詢日本智財律師（初次） | 見 [風險登記表](10-risk-register.md) |

**驗收標準：**

- 「聽膩／曲目重複」進入不滿排序前三名的比例 **≥ 50%**
- 至少 5 家表達「若有証明書會更安心」

**中止條件：** 若「聽膩」未進前三，**定位必須重寫**。屆時候選方向：純法規合規切入（等待レコード演奏・伝達権 施行）、或轉向店舖專屬客製曲庫的高單價利基市場。

> 這 3 週能省下半年的錯誤開發。不要跳過。

---

## Phase 1 — 曲庫地基（6〜8 週）

沒有乾淨的曲庫，後面全部無意義。

| 交付 | 內容 |
|---|---|
| 上傳與轉檔管線 | 直傳 R2 → ffmpeg → HLS + 商用 AAC → LUFS 量測 |
| 權利聲明表單 | `rights_declarations`，CHECK 約束強制 |
| 自動審核 | 指紋、CLAP 嵌入、平台內去重 |
| 人工審核後台 | 佇列、判定、`clearance_checks` 記錄 |
| 創作者 Profile | handle、bio、外部連結 + `rel="me"` 驗證 |
| 聽眾端 Web 播放 | 情境瀏覽 + 免費串流 |
| 稽核軌跡 | `audit_events` 全面接上 |

**驗收標準：**

- `cleared` 曲目 **≥ 3,000**
- 全部曲目 LUFS 落在 -16 ± 1
- 人工審核的平均處理時間 < 48 小時
- 隨機抽查 100 首，J-WID／NexTone 命中 **0** 件

**中止條件：** 若無法在 8 週內累積 3,000 首乾淨曲目，供給側是瓶頸 —— 需先解決創作者招募，再繼續。

## Phase 2 — 商用化（8〜10 週）

| 交付 | 內容 |
|---|---|
| 情境引擎 | 規則、選曲演算法、`exclude_played_within_hours` |
| Android 播放器 | ExoPlayer、離線快取、kiosk 鎖定、開機自啟 |
| 再生ログ | 事件上傳、冪等、append-only 儲存 |
| **管理外証明書** | 發行、PDF、公開驗證頁、店頭掲示物列印檔 |
| Stripe Billing | 訂閱、Webhook、寬限期、適格請求書 |
| 店主端 UI | 單頁控制 + 一鍵顯示証明書 |
| 撤銷流程 | 差分同步、緊急推播、受影響店家查詢 |

**驗收標準：**

- 付費店舖 **50 家**
- 月流失率 **< 3%**
- 離線 7 日後恢復，**零事件遺失**
- 撤銷演練：從標記到店內停播 **< 6 小時**
- 証明書驗證頁可被第三方獨立存取

**中止條件：** 若 50 家的目標在 10 週內達成率低於 40%，需重新檢視定價與銷售管道，暫緩 Phase 3。

---

## Phase 3 — 規模化（12 週+）

| 交付 | 內容 |
|---|---|
| 分潤系統 | `payout_periods`、Connect Transfer、防刷偵測 |
| 季度重掃 | 全曲庫 + 創作者會員身分重查 |
| Merkle root | 曲庫快照的可驗證證明 |
| 再生ログ 遷移 ClickHouse | 雙寫平滑切換 |
| Custom 方案 | 店舖專屬曲庫生成、多分店管理、API |
| 專用硬體 | 預裝 Android box |
| 連鎖店銷售 | Enterprise 方案、SLA |

**驗收標準：**

- 付費店舖 **500 家**
- 曲庫污染事件 **0**（紅線，非目標）
- 分潤準時撥付率 **> 99%**
- 曲庫規模 **≥ 30,000** 首

## 明確延後的項目

| 項目 | 何時再考慮 |
|---|---|
| P2P 卸載 | 頻寬帳單實際超過每月 US$500 時（以 R2 而言可能永遠不會） |
| iOS 播放器 | 店舖端以 Android 為主，需求不明確 |
| 日本以外市場 | 500 店穩定後 |
| 單曲販售 | 目前無計畫 —— 與 B2B 訂閱模式衝突且單位經濟不佳 |
| 社群功能（追蹤、留言） | 曲庫供給穩定後再評估；審核成本高 |
| 歌單策展分潤 | 聽眾端規模足夠時（目前聽眾端為曝光管道，非收入來源） |
