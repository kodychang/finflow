# 04 — 權利鏈設計

> **本文件是整個產品的價值來源。** 店家付費購買的不是音樂本身（廉價替代品到處都是），而是**「這些音樂可以合法在營業場所播放」這件事的可信度與可舉證性**。權利鏈一旦斷裂，產品即失去全部商業價值。

---

## 1. 法律定位

### 1.1 用語必須精確

| ✅ 使用 | ❌ 禁止使用 |
|---|---|
| 「JASRAC・NexTone 管理外の楽曲のみを配信」 | 「JASRAC を回避」 |
| 「著作権管理団体への申請が不要」 | 「JASRAC にお金を払わなくて済む」 |
| 「オリジナル楽曲のみで構成」 | 「著作権フリー」（語意模糊，易生誤解） |

**理由不是修辭，是法律位置。** 「管理外」是事實陳述；「規避」則暗示對既存權利的閃避，一旦發生曲庫污染，可能被主張明知並誘導侵權。此規範適用於所有對外文案、銷售話術與客服回覆，列入行銷素材審核檢查表。

### 1.2 「沒有販售」不等於「不需要授權」

日本著作權法第 22 條的**演奏權**規範的是「向公眾演奏、播放」這個行為本身，**與是否販售該音樂無關**。店家在營業場所播放音樂即屬公開再生，必須取得權利人許可。

差別僅在於**向誰取得**：

| 情況 | 授權來源 |
|---|---|
| JASRAC 管理曲 | JASRAC |
| **本平台曲目** | **權利人本人 → 即上傳者** |

因此上傳者條款**必須**授予平台可再授權（sublicensable）的公開演奏／再生權，才能轉授予商業訂閱戶。這對應到 `rights_declarations` 的 `grants_public_performance` 與 `sublicensable` 兩個欄位，且以 CHECK 約束強制為 true —— **缺了這一環，店家客戶在法律上仍屬無授權播放。**

### 1.3 レコード演奏・伝達権（2026 年修正）

新設的報酬請求權由指定團體統一徵收，最遲 2029 年 6 月施行。

**平台的分析立場：**

- AI 生成音樂**無人類實演家** → 無實演家報酬請求權
- **錄音製作者為上傳者本人**，其權利未委託任何指定團體 → 該團體無權就此收取
- 且平台曲目非以販售為目的製作，是否構成「商業用レコード」本身即有疑義

**但實務風險在於徵收方式。** 若指定團體採概括徵收，店家可能需自行舉證所播放內容不在管理範圍內。這使得**管理外証明書與再生ログ 從加分功能升級為必要功能**。

> 施行日期確定後、指定團體的使用料規程公布時，必須重新檢視本節。列為 [風險登記表](10-risk-register.md) 的追蹤項目。

## 2. 污染 — 唯一的存亡風險

**只要一首曲目出問題，平台對「所有」店家的保證同時失效。** 這不是可以事後補救的錯誤，是會直接摧毀商業模式的事件。

### 四種污染來源

| # | 來源 | 為何危險 |
|---|---|---|
| 1 | 上傳者本身是 JASRAC 會員 | 會員作品原則上**全部**委託管理，包含本人已遺忘的舊作 |
| 2 | 上傳他人作品，或 AI 生成出與既有作品高度近似的結果 | 日本法下具「依拠性 + 類似性」即可能構成侵權 |
| 3 | **事後**登記進 JASRAC | 最陰險 —— 當初查核時確實乾淨 |
| 4 | 既有作品的翻唱／改編 | 改編權仍屬原作者 |

### 對應防線

| 污染源 | 防線 | 實作 |
|---|---|---|
| 1 | 入口聲明 + 會員身分強制人工審核 | `rights_declarations.cmo_member` |
| 2 | 指紋比對 + 嵌入近似度檢測 | `clearance_checks` |
| 3 | **契約禁止事後登記 + 定期重掃** | `no_future_registration` + 季度重掃作業 |
| 4 | 原創性聲明 + 指紋比對 | `original_work` + `fingerprint_commercial` |

> **第 3 項最容易被忽略。** 光在上傳時查核不夠 —— 創作者日後加入 JASRAC，其作品會被自動納入管理。必須有**季度全曲庫重掃**機制（見第 5 節）。

## 3. 審核管線

```
上傳
 │
 ├─[1] 格式驗證 ─────── 非可解碼音訊 → reject
 ├─[2] 聲明完整性 ───── CHECK 約束不符 → 拒收（前端即擋）
 ├─[3] 平台內去重 ───── audio_sha256 已存在 → reject
 ├─[4] 指紋比對 ─────── 命中商業曲庫 → flag
 ├─[5] 嵌入近似度 ───── cosine > 0.92 對既有商業作品 → flag
 ├─[6] J-WID 查核 ───── 曲名/作者命中 JASRAC 作品庫 → flag
 ├─[7] NexTone 檢索 ─── 命中 → flag
 ├─[8] 聲音克隆檢測 ─── 疑似模仿可辨識人聲 → flag
 │
 ├─[9] 人工審核 ──────── 全部 flagged + 依信譽等級抽樣
 │       trust_tier 0 → 100% 人工   （新帳號）
 │       trust_tier 1 → 30%
 │       trust_tier 2 → 10%
 │       trust_tier 3 → 3%          （長期無事故）
 │
 └─[10] cleared → 可加入 commercial_catalog_entries
```

**設計要點：**

- 任一步驟的結果（含通過）都寫入 `clearance_checks`，保留 `evidence`。**遭質疑時要能重現當初的判斷依據，只存結論是不夠的。**
- `inconclusive`（例如外部 API 逾時）**視同 flag**，不得自動放行。
- **新帳號一律 100% 人工審核。** 這是成本最高但最不能省的一道防線。
- 只有 `cleared` 才可能進入商用曲庫；`cleared` 也不代表自動進入 —— 加入 `commercial_catalog_entries` 是獨立的一步。

### 3.1 J-WID / NexTone 查核的現實限制

兩者皆為網頁檢索介面，無公開 API。實作方式：

1. **建立本地快取索引** —— 定期抓取並建立可比對的本地資料（須確認各站服務條款允許的存取方式與頻率）
2. 以「曲名」+「作者名（上傳者本名與藝名）」雙軸比對
3. **創作者本名查核優先於曲名查核** —— 若上傳者本人為會員，其全部作品皆有風險，比逐首查曲名更關鍵

> 存取方式與頻率須先確認合法性，列入 [風險登記表](10-risk-register.md)。若條款不允許自動化存取，退回「人工查核 + 上傳者提供非會員證明」的流程。

## 4. 撤銷（revocation）

當已 `cleared` 的曲目被發現有問題時的處理程序。**這是最高風險事件，必須有預先演練過的流程。**

```
發現問題（檢舉 / 重掃命中 / 權利人通知）
 │
 ├─[T+0]   立即從 commercial_catalog_entries 移除（removed_at）
 │         → 商用播放器在下次同步時停止播放（最長 6 小時）
 │         → 高危事件可透過推播強制即時同步
 ├─[T+0]   track_versions.clearance = 'revoked'，寫入 audit_events
 ├─[T+1h]  查詢 playback_events：找出所有曾播放此曲的店舖
 ├─[T+24h] 主動通知受影響店家，提供：
 │           - 該曲的完整播放記錄
 │           - 平台的處理說明與時間軸
 │           - 若產生實際請求，依條款由平台承擔
 ├─[T+48h] 向上傳者追究契約責任
 └─[T+7d]  事後檢討：此曲為何通過審核？補強對應防線
```

**主動通知是關鍵。** 隱瞞會讓一次技術失誤升級為信任崩塌。條款中應明確承諾此通知義務 —— 這本身就是銷售賣點。

**檔案不硬刪。** `revoked` 曲目的原始檔保留於冷儲存以備稽核，僅移出 CDN 與商用曲庫。

## 5. 季度重掃

排程作業，每季對**全部 `cleared` 曲目**重跑步驟 [4]〜[8]，重點在於捕捉「事後登記」。

```sql
-- 重掃對象
SELECT tv.id, tv.audio_sha256, t.title, u.display_name
FROM track_versions tv
JOIN tracks t ON t.id = tv.track_id
JOIN users u ON u.id = t.creator_id
WHERE tv.clearance = 'cleared'
  AND (tv.last_rescanned_at IS NULL
       OR tv.last_rescanned_at < now() - interval '90 days');
```

同時對**所有活躍創作者**重查集管團體會員身分 —— 這比逐首重查曲名更有效率，也更能捕捉風險。

## 6. 責任與賠償鏈

```
上傳者 ──保證 & 賠償──▶ 平台 ──保證 & 賠償──▶ 店家
```

**上傳者條款須包含：**

- 聲明內容真實；違反時對平台負賠償責任
- 不得日後將作品委託任何集管團體
- 授予平台可再授權的公開演奏／再生權，及為此進行編碼、快取、分發的必要權利
- 平台有權隨時移除任何曲目，無須說明理由

**店家條款須包含：**

- 平台保證曲庫全部為 JASRAC／NexTone 管理外
- 若店家因使用本服務曲目而遭第三方請求，平台承擔抗辯與賠償（設上限，例如該店已付訂閱費之 12 倍）
- 店家須將播放限於已訂閱之場所，不得外流商用音檔

**保險：** 應洽詢日本產險公司投保智財責任險。上述賠償承諾若無保險支撐，在真的發生大規模事件時無法履行 —— 而無法履行的承諾，比不承諾更糟。

## 7. 明確禁止事項

| 禁止 | 原因 |
|---|---|
| 模仿可辨識在世人物的聲音 | 日本パブリシティ権（最高法院 2012 年ピンク・レディー事件）；且 2024 年起聲優界對 AI 聲音複製的關注度極高 |
| 上傳既有作品的翻唱、改編、混音 | 改編權屬原作者 |
| 使用未授權取樣 | 錄音著作隣接権 |
| JASRAC／NexTone 會員上傳未經證明的作品 | 污染來源 #1 |
| 曲名或藝名蹭既有知名作品 | 混淆風險 + 招致主動稽查 |

**AI 訓練資料的立場：** 日本著作權法第 30 條之 4 對 AI 訓練相對寬鬆，是有利條件。但**生成結果**若與既有作品構成「依拠性 + 類似性」仍會侵權。因此步驟 [4][5] 的指紋與嵌入比對不可省略 —— 訓練合法不代表輸出安全。
